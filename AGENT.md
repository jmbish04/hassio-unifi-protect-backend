# UniFi Protect API Worker - Agent Documentation

## Overview

This Cloudflare Worker serves as the **backend API** for UniFi Protect integration. It acts as a bridge between frontend workers/clients and the FastAPI service, handling authentication, camera management, and security sweep operations.

**Important**: This is the **backend worker** - frontend workers should connect to this worker's API endpoints, not directly to the FastAPI service.

## Architecture

### System Architecture

```
UniFi Protect Cameras → FastAPI Service → Backend Worker (this) → Frontend Worker → Browser
```

The system uses a four-tier architecture:

1. **FastAPI Service** (`PROTECT_API`):
   - Handles RTSP to HLS conversion using ffmpeg
   - Generates session tokens for browser authentication
   - Manages HLS stream lifecycle and serving
   - Provides WebSocket connections for real-time status updates
   - Direct UniFi Protect API access with `PROTECT_API_KEY`

2. **Backend Worker** (this worker):
   - **Proxies all FastAPI endpoints** to frontend workers
   - **Manages authentication** with `WORKER_API_KEY`
   - **Provides additional features** (security sweeps, webhooks, etc.)
   - **Serves API documentation** and health checks
   - **Single entry point** for all frontend workers

3. **Frontend Worker** (separate worker):
   - **Consumes backend worker endpoints** for live camera streams
   - **Handles user interface** and camera grid display
   - **Manages session tokens** for HLS authentication
   - **Displays live video streams** using Video.js/HLS.js
   - **Real-time updates** via WebSocket connections

4. **Browser/Home Assistant**:
   - **Consumes frontend worker** for user interface
   - **Receives live camera streams** through frontend worker

### Authentication Flow

- **Backend Worker → FastAPI Service**: Uses `PROTECT_API_KEY` with `x-api-key` header
- **Frontend Worker → Backend Worker**: Uses `WORKER_API_KEY` with `x-api-key` header
- **HLS Streams**: Uses Bearer tokens generated by `/proxy/session/token`

### Key Services

- `ProtectApiService`: Handles UniFi Protect API communication
- `SecuritySweepService`: Manages security patrol operations
- `HomeAssistantClient`: Integrates with Home Assistant
- `VisionAnalysisService`: Processes camera images with AI
- `CameraService`: Manages camera operations
- `RulesEngine`: Evaluates security rules
- `StorageService`: Handles D1 database operations
- `NotificationService`: Sends alerts via ntfy

## API Endpoints

### Public Endpoints

- `GET /` - Serves the main dashboard
- `GET /favicon.ico` - Returns 204 No Content
- `GET /openapi.json` - API documentation

### Protected Endpoints (require WORKER_API_KEY)

- `GET /protect/cameras` - List all cameras
- `GET /protect/cameras/{id}` - Get specific camera
- `GET /protect/cameras/{id}/streams` - Get camera streams
- `POST /protect/login` - Login to UniFi Protect

### HLS Streaming Proxy Endpoints (require WORKER_API_KEY)

- `POST /proxy/session/token` - Generate session token for HLS authentication
- `POST /proxy/hls/{camera_id}/start` - Start HLS proxy for camera
- `GET /proxy/hls/{camera_id}/{filename}` - Serve HLS stream segments (requires Bearer token)
- `GET /proxy/hls/{camera_id}/ws` - WebSocket for real-time stream status (requires Bearer token)

## Frontend Worker Integration

### For Frontend Worker Developers

If you're building a frontend worker that consumes this backend worker API:

#### **Base URL**
```
https://your-backend-worker.your-subdomain.workers.dev
```

#### **Authentication**
All requests must include the `x-api-key` header:
```javascript
const response = await fetch(`${BACKEND_WORKER_URL}/protect/cameras`, {
  headers: {
    'x-api-key': 'YOUR_WORKER_API_KEY'
  }
});
```

#### **HLS Stream Integration**
1. **Get session token**:
   ```javascript
   const tokenResponse = await fetch(`${BACKEND_WORKER_URL}/proxy/session/token`, {
     method: 'POST',
     headers: { 'x-api-key': 'YOUR_WORKER_API_KEY' },
     body: JSON.stringify({ camera_id: 'camera_id' })
   });
   const { token } = await tokenResponse.json();
   ```

2. **Start HLS proxy**:
   ```javascript
   const startResponse = await fetch(`${BACKEND_WORKER_URL}/proxy/hls/${cameraId}/start`, {
     method: 'POST',
     headers: { 'x-api-key': 'YOUR_WORKER_API_KEY' },
     body: JSON.stringify({ quality: 'medium' })
   });
   const { proxy_hls_url } = await startResponse.json();
   ```

3. **Access HLS stream**:
   ```javascript
   const streamUrl = `${BACKEND_WORKER_URL}${proxy_hls_url}`;
   // Use with Video.js or HLS.js with Bearer token authentication
   ```

#### **Important Notes**
- **Never connect directly** to the FastAPI service from frontend workers
- **Always use this backend worker** as the single entry point
- **Session tokens expire** in 10 minutes - implement refresh logic
- **WebSocket connections** require Bearer token authentication

## HLS Video Streaming Implementation

### Architecture Overview

The system provides live camera streaming through a three-tier architecture:

1. **FastAPI Service** (`PROTECT_API`): Converts RTSP streams to HLS format using ffmpeg
2. **Cloudflare Worker**: Proxies FastAPI endpoints and manages authentication
3. **Frontend**: Displays live streams using Video.js and HLS.js

### Authentication Flow

1. **Session Token Generation**: Frontend calls `POST /proxy/session/token` with `WORKER_API_KEY`
2. **HLS Proxy Start**: Frontend calls `POST /proxy/hls/{camera_id}/start` to initialize stream
3. **Stream Access**: Frontend uses Bearer token for HLS segment requests

### Frontend Implementation

The frontend automatically:
- Initializes HLS streams for all connected cameras on page load
- Uses Video.js with HLS.js for cross-browser compatibility
- Provides real-time status updates via WebSocket connections
- Handles authentication and error states gracefully

### Stream Display Features

- **Real-time Status**: WebSocket connections for live stream status updates
- **Error Handling**: Comprehensive error handling for stream failures
- **Responsive Design**: Mobile-optimized camera viewer interface

## Common Issues & Solutions

### 1. API Authentication Errors

- **401 Unauthorized**: Check `WORKER_API_KEY` for client requests
- **422 Missing x-api-key**: Ensure `PROTECT_API_KEY` is set for UniFi Protect calls

### 2. UniFi Protect API Issues

- **404 Not Found**: Verify API endpoint paths (use `/protect/login` not `/api/auth/login`)
- **500 Internal Server Error**: Check if UniFi Protect service is running

### 3. Environment Variable Issues

- Always verify `.dev.vars` file contains all required variables
- Run `wrangler types` after changing environment variables

### 4. Camera Stream Display Issues

- **Unknown Camera IDs**: Check database field mapping (`camera_enum_id` vs `cameraId`)
- **Unknown Event Types**: Verify webhook event field mapping (`event_type` vs `eventType`)
- **Stream Not Loading**: Check `/ui/worker-agent-prompt` for stream implementation details

## Development Workflow

1. **Apply Database Migrations**: `pnpm migrate:local` (CRITICAL for first run)
2. **Start Development Server**: `pnpm dev`
3. **Test Endpoints**: Use curl or the web interface
4. **Update Types**: `pnpm cf-typegen` after configuration changes
5. **Run Checks**: `pnpm check` (REQUIRED before committing - validates types and formatting)
6. **Deploy**: `pnpm deploy` (automatically runs remote migrations first)

### Pre-Commit Checklist

**ALWAYS run these checks before committing code:**

```bash
pnpm check          # Run all checks (types + formatting)
pnpm check:types    # TypeScript type checking only
pnpm check:format   # Code formatting validation only
pnpm format         # Auto-fix formatting issues
```

These checks replicate VSCode's Problems tab and will catch:

- TypeScript errors in src/ and test/ directories
- Type safety issues
- Code formatting inconsistencies

**Do not commit code with type errors!** Fix all issues reported by `pnpm check` first.
